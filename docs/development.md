# Local development

The app is an Expo SDK 58 project. Routes live in `src/app`. Domain code does not import Expo except at the edges: `src/db/expoAdapter.ts`, `src/db/open.ts`, `src/notifications/native.ts`, and `src/backup/files.ts`.

## Layout

- `src/app` — screens. Bottom tabs are Home, Curriculum, Revision, Progress, and Settings.
- `src/curriculum` — bundled lessons. Days 1–14 are full sessions. Days 15–210 are planned.
- `src/engine` — dates, self-assessment, spaced repetition, streaks, heatmap, and the next lesson. These modules are pure.
- `src/db` — SQLite migrations and the repository. The database file is `sysdapp.db`.
- `src/notifications` — reminder planning is pure. The native module only schedules what the planner returns.
- `src/backup` — JSON validation, plus the share sheet and document picker adapters.
- `src/state/AppProvider.tsx` — opens the database, loads a snapshot, and reconciles reminders.
- `test` — Node’s test runner and `node:sqlite`. Tests are not part of the app bundle.

## Commands

```bash
npm install
npm test
npm run typecheck
npx expo start
```

`npm test` loads TypeScript through Node’s strip-types loader. `test/register.mjs` appends `.ts` to extensionless imports so the same source can run in Metro and in Node. Do not set `"type": "module"` in `package.json`; that setting conflicts with the Expo package.

`npm run typecheck` uses `tsc --noEmit` and excludes `test/`.

## Offline launch

Curriculum content is imported from TypeScript. Progress is read from SQLite during startup. A failure to schedule notifications is caught so the lesson screens still open. Optional resource links are opened only after you confirm an alert; the lessons themselves do not fetch them.

## Native projects

`ios/` and `android/` are generated by Expo prebuild. Do not edit them by hand. Change `app.json` and run prebuild again when you need a development build.
